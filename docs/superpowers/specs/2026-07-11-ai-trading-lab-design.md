# AI 交易實驗室 — 設計規格

日期：2026-07-11
狀態：設計已由 arlong 口頭核准（本文件為書面化）
背景：YT 頻道（AL_Story）2026-07-06 遭終止後，A（crime→TikTok/FB）+ B（pixel_battle）
於 2026-07-09 被放下（原因：題材風險心累、無熱情、變現太遠）。本方向為全面重來的新定位。

## 0. 一句話定位

Faceless 中文短影音品牌：**用真實數據記錄 AI 自動交易實驗** —— 模擬盤明示、
虧損照報、每個數字可程式對帳。TikTok + FB Reels 手動上傳，導購變現，不給投資建議。

## 1. 為什麼是這個方向（決策紀錄）

- arlong 的釐清答案：徹底重來／主因＝風險心累＋無熱情＋變現太遠／
  題材＝投資金融＋AI 工具／完全 faceless／平台 TikTok+FB＋導購變現
- 對「假內容重演」質疑的結構性回答：crime 的事實在外部世界（LLM 回憶→幻覺），
  本方向的事實在自家系統（結構化數據注入→LLM 只做敘述）。財經數字可逐字元
  程式對帳，比敘事查證強一個等級。
- 內容自產：pikmin trading bot 與 poly_market 掃描器持續產生數據，選題不會枯竭。

## 2. 數據源（2026-07-11 實際盤點）

| 來源 | 路徑 | 格式 | 狀態 |
|---|---|---|---|
| pikmin 日報 | `~/Projects/pikmin-command-center/trading/daily_reports/*.json` | equity/total_pnl/pnl_pct/trades/fees/grid 指標 | 55 份；**最後一份 2026-06-11，cron 需修復（前置任務）** |
| 權益曲線 | 同目錄 `equity_curve.png` | PNG | 有 |

**關鍵誠實要點**：pikmin 為 `live_dry` 模擬盤（虛擬 $1,564、49 天、500 筆）。
所有內容必須明示「模擬盤實驗」，禁止暗示實盤獲利。若未來轉實盤，內容框架同步升級。

## 3. 內容形式（三型輪替，60-90s 直式）

1. **實驗週報**（週 1）：「AI 操盤第 N 週：±X%」— 權益曲線動態 + 本週最佳/最差交易
   + 下週懸念。數據源：daily_reports + equity_curve。
2. **策略拆解**（週 1）：「AI 在 Polymarket 找到的套利機會」「網格策略如何運作」。
   數據源：poly_market 掃描/回測 MD/CSV。
3. **建置幕後**（雙週 1）：「我怎麼用 AI 蓋出交易機器人」— AI 工具題材的自然混入，
   為工具聯盟變現鋪路。

冷啟動節奏依 `docs/pivot_playbook.md`：前 2-3 週日發 ≤1、時間不規律、手動上傳。

## 4. 架構

```
market_data_ingest.py (新)          # 讀兩專案產出 → 標準化「數據包」JSON
  → 腳本生成 (改)                    # 新 prompt：注入數據包，敘述性、無宏觀評論
  → 數字對帳閘門 (新)                 # 腳本中每個數字 ∈ 數據包，否則 fail-closed
  → 圖表視覺模組 (新)                 # matplotlib 產權益曲線/交易點位圖 → 9:16
  → TTS + Remotion 組裝 (重用)
  → QA (重用 + 新增數字對帳與免責聲明存在性檢查)
  → export_reel.py 打包 (重用)       # TikTok/FB 文案 + 免責聲明 + referral 連結
```

產線重用 ~80%。新模組三個，均為獨立可測單元：
- `market_data_ingest.py`：輸入=兩專案檔案路徑；輸出=數據包 JSON
  （期間、期初/期末權益、pnl、pnl_pct、trades、最佳/最差交易、fees、天數）。
  只讀，不改源專案。
- 數字對帳閘門：輸入=腳本文字+數據包；比對腳本中所有數值 token（含百分比、
  金額、天數、筆數；容許四捨五入到數據包值的顯示精度）；任何無源數字→拒絕渲染。
  實作於腳本生成後、TTS 前。
- 圖表視覺：v1 靜態 matplotlib（深色主題延續 noir 品牌感）+ 現有 Ken Burns/
  DepthFlow 視差；動畫化圖表為 v2。

## 5. 真實性防線（硬性，缺一不發）

1. 數字對帳 fail-closed（上述閘門）
2. 「模擬盤實驗」標示：畫面固定角標 + 文案首段
3. v1 禁宏觀評論：prompt 明文禁止敘述外部市場事件因果（消滅外部事實幻覺面）；
   若未來開放，必須接既有 search-grounding
4. 虧損照報：週報數據為負就照做負的 —— 誠實是定位的一部分
5. 禁詞 backstop（沿用敏感案件機制）：保證獲利、必賺、穩賺、跟單、帶單、老師

## 6. 法遵（台灣投顧法紅線）

- 每支影片：畫面免責聲明 +文案「模擬盤實驗紀錄，非投資建議」
- 禁止：推薦個股/標的、喊單、付費群、暗示跟隨操作可獲利
- prompt override + 禁詞 backstop 雙層（同 crime 敏感案件架構）

## 7. 變現

- 第一天起：文案掛交易所/券商 referral（arlong 實際使用者優先，待他提供連結）
  + AI 工具聯盟（建置幕後型影片）
- 粉絲量成長後再評估：社群/訂閱制。分潤（FB 邀請制）為長線被動項。

## 8. MVP 範圍（第一個實作循環）

1. 前置：修復 pikmin daily_reports cron（或 arlong 指定替代數據源）
2. `market_data_ingest.py` + 數據包 schema
3. 數字對帳閘門 + 單元測試（含容錯：四捨五入、千分位、百分比格式）
4. 週報 prompt（敘事模板 + 免責 + 禁詞）
5. matplotlib 深色權益曲線 9:16 圖
6. 端到端一支「實驗週報」樣片 → 視覺驗收 → upload_package
7. 品牌名：arlong 定案前用佔位（不 block 開發）

**非目標（v1 明確不做）**：宏觀市場評論、動畫化圖表、自動上傳、
Polymarket 策略拆解型（第二循環）、YouTube。

## 9. 風險與緩解

| 風險 | 緩解 |
|---|---|
| 模擬盤被誤解為實盤 | 固定標示 + 文案首段明示（防線 2） |
| LLM 加油添醋市場因果 | v1 禁宏觀評論（防線 3） |
| 數字錯誤 | 對帳閘門 fail-closed（防線 1） |
| 平台 spam 歸類 | playbook 冷啟動鐵則照舊 |
| 數據斷供（cron 停） | 前置任務修 cron；ingest 對過期數據（>48h）警告拒跑 |
| 投顧法 | 免責 + 禁詞 + 不推標的（§6） |
